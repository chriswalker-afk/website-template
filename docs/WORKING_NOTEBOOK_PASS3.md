# Pass 3 — Working notebook integration across learning modes

## What changed

Pass 2 established one reusable typed/drawn notebook. Pass 3 **reuses** it in
the three extended-response modes and the independent example in Understand.
No separate drawing engines, duplicated mathematical editors, remote backends
or automatic free-response graders were introduced.

| Mode | Notebook scope | Student experience |
| --- | --- | --- |
| Understand | Topic / worked-examples subsection / page / `my-turn` | Independent “My turn” scratchwork, diagram, maths and step-by-step explanation alongside existing model/hint/self-check |
| Reasoning | Topic / reasoning subsection / prompt | Dedicated notebook for every argument; student can declare that the argument is in the notebook rather than the plain-text box |
| Problem Solving | Topic / level / book page / problem | Dedicated problem notebook; strategy and working confirmations are independent |
| Modelling | Topic / level / book page / scenario | **One notebook shared across Formulate → Calculate → Interpret → Evaluate and the final comparison**, with separate confirmations at each stage |

Stable scopes are generated by `workingScope()` in
`src/working-notebook-integration.js`. Content is stored locally under the
existing `maths-notebook:working:v1:` prefix. Round changes and switching
practice selections **do not destroy** the saved notebook. Complete-set views
include an archive linking all task-scoped notebooks for review and export.

## Self-review is not automatic marking

Existing scoring/review rules are preserved:
- Understand remains a guided, student-controlled comparison with the worked model.
- Reasoning still requires an attempted argument and all three self-check
  criteria for a “Ready” rating.
- Problem Solving still requires a strategy, working and three checks, and
  continues to distinguish independent from assisted attempts.
- Modelling still requires evidence at **all four stages** and all three
  evaluation checks; guided/model-first work cannot be self-rated independent.

Previously, those attempts could only be recognised from the plain-text
response fields. A student who used proper typed mathematics or handwritten
working in the notebook would otherwise be blocked from self-review.
Pass 3 therefore adds **explicit student confirmation** controls:

- Reasoning: “My mathematical argument is recorded in the notebook.”
- Problem Solving: separate strategy and mathematical working confirmations.
- Modelling: a separate notebook confirmation in each of the four stages.

A confirmation is accepted only when the relevant notebook has nonempty
content. An entry is checked again when the student opens worked help or
submits a self-review: clearing the notebook invalidates stale confirmations.
The review remains the **student's judgement**, never machine recognition
of handwriting, auto-assessment of equations or a teacher mark. A student
must affirm that the content actually addresses the task/stage; the site
does not pretend to verify semantic correctness.

The short plain-text response boxes are still available and still work
exactly as before. A learner can mix them with notebook evidence.

## Safeguards and privacy

- Every task has its own notebook; **no answer leaks into another question**.
- In Modelling, evidence is confirmed per stage, but the visual notebook is
  shared so a student can refer back to assumptions/calculations.
- Textarea drafts and the stage self-review confirmations remain ephemeral
  session state; **mathematical notebook content** is separately autosaved in
  browser-local storage. Saved progress contains only previous rating/status
  aggregates, not the written mathematics or handwritten strokes.
- The notebook can be exported as printable HTML (with SVG pen strokes) or
  backed up as JSON; drawing, local storage and source-LaTeX fallback work
  without an internet connection. Initial loading of the MathLive visual
  editor still requires the pinned CDN.
- On a shared device/browser profile, subsequent users can see local
  notebooks. Students should export important work and clear it deliberately
  on shared devices.
- Limits, escaping, no-eval parser and strict restore validation from Pass 2
  remain unchanged.

## Validation

Unit tests assert deterministic/safe task scoping, authentic nonempty
working evidence, stale-confirmation rejection, separate mode attempts,
criterion gates, mode-specific rendering and completed-work archives.
Playwright covers typed/drawn work in every mode, modelling stage continuity,
local refresh recovery, no automatic grading, preserved self-review and
a 320px responsive check.

### Follow-on improvements (not part of Pass 3)

A device-local notebook library/management dashboard, import of JSON backups,
pressure-sensitive pen strokes, annotation directly on interactive diagrams,
offline packaging of MathLive, and optional class/teacher submission could be
developed later. The core workspace remains qualification-neutral.
