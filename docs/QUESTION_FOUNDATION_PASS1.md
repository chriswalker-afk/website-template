# Question-generation foundation — Pass 1

This is an **additive, opt-in API** in `src/question-foundation/`. Existing Sampling,
Quadratics and Gradient families, seeded outputs, progress keys, numerical marking and
worksheet/LaTeX behaviour are intentionally unchanged.

## Source of truth

Use `makeQuestionModel({topicId,familyId,signature,parameters,prompt,marks,answer,
solutionSteps,hint,skill,misconception,difficulty})`.

- `signature` is stable and derived from parameter values. It must not include a
  random invocation ID. The shared adapter prefixes it with the family ID.
- `parameters` contain the mathematical inputs, not preformatted question text.
- `answer` explicitly declares a kind. Supported model kinds are number, ordered,
  unordered, rational, expression, equation, inequality, interval, coordinates,
  set, choice and self-review. **Only the first three can currently be automatically
  marked by the existing Fluency checker.** Other kinds are authoring contracts
  awaiting Pass 2, not claims of verified symbolic equivalence.
- `solutionSteps` and `hint` must be reviewed; the foundation does not
  infer a proof or mathematical solution from the prompt.

## Deterministic parameter helpers

`integer`, `nonZeroInteger`, `choice`, `shuffled`, `distinct`,
`gcd`, `rational`, `rationalChoice` all use a supplied seeded RNG where
randomness is needed. No `eval`, `Math.random()`, remote dependency or
dynamic execution is involved. Rational values normalise signs and reduce.

## Presentation adapters

`presentQuestion(model, 'fluency')` returns the existing numerical Fluency
question shape and explicitly rejects unsupported answer types. It preserves
legacy `family`, prefixed `signature`, `answer`, `steps`, `hint` and
`mistake` keys.

`presentQuestion(model, 'worksheet', {questionTex,answerTex,solutionTex,hintTex,
spaceMm})` returns the existing printable family output. All LaTeX fields
must be teacher-authored/reviewed; they are never auto-generated by parsing
arbitrary prose. `presentQuestion(model, 'worked-example')` gives a simple
prompt/steps/hint view.

A new topic may adopt the model incrementally. To migrate a legacy family,
verify unchanged seeds, signatures, question wording, worked solutions and
accepted answers before switching it. Do **not** wholesale convert existing
packs or change local student progress keys.

## Example

```js
import {makeQuestionModel,presentQuestion,integer} from '../../question-foundation/index.js';
const generate=rng=>{
  const run=integer(rng,2,6),gradient=integer(rng,1,3),rise=run*gradient;
  const model=makeQuestionModel({
    topicId:'gradient',familyId:'sample-rise-run',signature:run+':'+gradient,
    parameters:{run,rise,gradient},prompt:`A line rises ${rise} over a run of ${run}. Find its gradient.`,
    marks:2,answer:{kind:'number',values:[gradient]},
    solutionSteps:[`Signed rise = ${rise}; run = ${run}.`, `Gradient = ${rise} / ${run} = ${gradient}.`],
    hint:'Divide rise by run.',skill:'Gradient',
    misconception:'Do not reverse rise and run.'
  });
  return presentQuestion(model,'fluency');
};
```

## Testing and next steps

Run `npm run check`, `npm run test:latex`, and `npm run test:browser`.
The new Node tests cover parameter bounds/reproducibility, model validation,
adapters, rejection of unsupported auto-marking and legacy Gradient smoke tests.

**Pass 2:** add trustworthy mathematical equivalence/answer verification
(including safe parsing, exact rational arithmetic, equivalent algebraic
expressions and inequalities), independent generated-question property tests,
and diagnostics that explain failures without pretending a numeric check proves
symbolic correctness. Retain explicit self-review for open-ended responses.
